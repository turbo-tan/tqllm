# Flash-Next hot/cold quality pilot

Private experiment, not a release feature. A manifest with `hot_map=PATH` uses an existing compact int32 per-layer expert map only to select precision. Entries >=0 retain the current GGUF format; -1 entries use the existing GSQ_Q2_0 64-weight format. No logits are masked and no routed weight is changed. Original expert ids remain valid. Duplicate assignments are preserved and each assignment is dispatched to exactly one format bank. Group lists, rather than invalid negative ids, limit each projection to that bank's assignments.

`cold_slots=16` controls a separate GPU cache backed by bounded on-demand host requantization from the shipped GGUF. Hot-bank capacity defaults to the map's hot count; optional `hot_slots=80` lowers GPU cache capacity without changing the map, original-format expert membership, global ids or routing. It requires `hot_map` and a value between1 and its hot count. At small budgets, choose enough slots for the verify wave while keeping a bank for every layer, rather than repeatedly evicting whole layers. Both tiers can evict banks under pressure; persistent residency is not guaranteed. This prototype intentionally uses small prefill chunks and a single session. The default pilot converts on demand; optional persisted cold storage is described below. It does not implement optimized asynchronous loading. Its timings are not a fair final performance comparison. Keep all precision changes opt-in.

The down projections have 640 columns, incompatible with unpadded Q2_K's 256-weight rows. GSQ_Q2_0 has 64-weight blocks (18 bytes) and fits every projection. Encoding from shipped quantized weights is a second lossy quantization, not quantization from BF16 originals. No quality improvement is presumed. Q2_K remains a possible future gate/up alternative with a separate down format.

F35 has 120,795,955,200 routed-expert weights. Keeping 154/512 original experts costs 15,312,281,600 packed bytes. The other 358/512 in GSQ_Q2_0 require 23,755,161,600 bytes, or 39,067,443,200 bytes combined before dense weights, KV, staging and metadata. All-resident operation is impossible on a 24 GiB card for this split. Cold host storage/cache is required.

Gates: CPU encoder/map validation; existing CUDA Q2 and cache oracles; paired basic quality screen against full routing; pagoda and BenchLoop; then corpus KL plus task quality and own-AR/spec checks. No adoption or speed-win claim before these gates. The 30-percent-pruned baseline failed the basic quality screen and is not a fallback.

Diagnostic follow-up: first pilot failed its first HTTP request with a range error after 534.7 s warm-up. No quality result. Numeric guards now report the first failing MoE layer or invalid route with counts of nonfinite values. Warm-up is one token, with the MTP warm batch limited to the available rows. CPU Q2 encoding has an opt-in call-site parallel implementation over independent64-weight blocks; tests require exact byte equality to serial output across1/2/8/32 workers, including error propagation. This affects conversion cost only.

Payload ownership fix: MixedExpertCache::prepare collects all missing experts before repacking them. The initial cold memo erased source buffers during that collection, leaving earlier GgufBytes views dangling. ExpertPayload now accepts an optional shared ownership token, retained by the incoming payload list. Cold memo entries share ownership with their returned payloads, so dictionary eviction cannot free pending data. The pilot memo is now3GiB on the32GiB host. The memo cap excludes the temporarily pinned incoming batch (at default16 cold slots, roughly22MiB extra). The deterministic GPU reproducer poisons buffers at semantic destruction without actual freed-memory access: old API exits1, fixed API passes. This fixes a demonstrated lifetime bug; real-model quality still needs to pass.

The bounded Q2 code decision uses exact half-integer thresholds in place of general round/clamp. Boundary and200001-ratio oracles plus a real-shape1.6384M-weight comparison require byte equality. Parallel source decode+encode splits at lcm(source block,64), tested against whole-buffer decoding for F32, IQ3_XXS, IQ4_NL and GSQ_Q2_0. Host conversion timing is not model decode throughput.

## Persistent cold Q2 store

Run `tq-cold-q2 MAP OUTPUT MAX_NEW_EXPERTS GGUF [GGUF ...]` before inference. This fixed-shape F35 converter writes one immutable record for each cold expert, in global expert-id order; zero means all remaining experts. A positive limit makes a bounded pilot. Resume validates existing records and skips them. Records publish by atomic rename, and a completion marker appears only after every cold expert exists. Keep at least 2 GiB disk reserve. One converter per directory; use an external file lock.

Add `cold_store=OUTPUT` alongside `hot_map` in the private manifest. The runtime requires a complete store with the same encoder revision, source canonical paths/sizes/mtime, projection size, and exact map bytes. This identity detects accidental input changes; it is not a cryptographic source-content hash. Record headers validate global layer/expert ids and a payload checksum. Missing, truncated, corrupt or mismatched data fails closed. No runtime requantization occurs with this option. Original hot formats, router weights and Q2 encoder arithmetic are unchanged. The existing bounded host memo and shared ownership remain in use.

The store occupies 23,755,711,488 bytes plus identity/completion files for this map (17,184 records including 32-byte headers). The primary speed gate is the same three prompts, greedy/closed-thinking/context4096/max8, comparing text and token counts against the on-demand run. This short test verifies function and conversion-cost removal; sustained decode speed and broader quality require separate gates.

Pinned prefill residual storage grows on first use to the actual prompt size. Startup does not lock host RAM for the full context capacity; the existing spec_begin growth path also handles larger later prompts. This changes allocation timing only, not stored values or arithmetic. Validate real-model output and request-size transitions before adoption.
