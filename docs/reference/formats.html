Inside TQ3_4S, TQ3 and TQ4: rotate first, then a small codebook

The TQ formats store a model's weights in blocks. Each block is rotated so no single weight sticks out, every weight becomes a 3-bit or 4-bit code, and a few scales set the size of the block. TQ3_4S uses blocks of 32 with four scales; TQ3 and TQ4 use blocks of 128 with one scale, so almost every bit goes into the codes.

4.0bits per weight, TQ3_4S (32-weight blocks, 8 levels)
3.125bits per weight, TQ3 (128-weight blocks, 8 levels)
4.125bits per weight, TQ4 (128-weight blocks, 16 levels)

What happens to one block of weights

A raw block has a few large weights and many small ones. Quantising it directly wastes most of the code levels on the rare outliers. A fixed rotation (a Hadamard-style transform with fixed signs over the whole block) spreads the outliers out, so the rotated values look alike and a small codebook fits them all. This is the TurboQuant idea applied to weights.

1 · rotate

Multiply the block by a fixed signed Hadamard rotation: 32 points in TQ3_4S, 128 in TQ3 / TQ4. No data is stored for it.

2 · scale

Pick the block scale (FP16 in TQ3 / TQ4, four 8-bit scales in TQ3_4S) so the codebook covers the rotated values.

3 · code

Store each weight as the index of its nearest level: 3 bits (8 levels) or 4 bits (16 levels).

4 · read

At run time the input is rotated once with the same transform, and the product runs directly on the codes and scales.

The bit budget, drawn to scale

Each strip is the storage for 128 weights, one cell per bit, all at the same scale. Codes are the bulk; the scales are what is left. TQ3_4S spends a quarter of its bits on scales, TQ3 and TQ4 about 3 %.

TQ3_4S is four 32-weight blocks, each with 96 bits of codes and four 8-bit scales (one per 8 weights). Shades inside the code area mark sub-blocks.

TQ3_4S was first: it works in a llama.cpp fork and in tqLLM, and it is what the Flash-Next expert files use. TQ3 and TQ4 rotate over a 4x longer block, so one scale per 128 weights is enough and the bits go into the codes instead. That is how Qwen3.8-27B fits in 11.85 GB as TQ3 (TQ_XS) against 14.5 GB as TQ3_4S, and why TQ4 at about the same size as TQ3_4S is much closer to the original. Type ids 300 and 301 are tqLLM's own, above the ggml range, so these files need tqLLM.

Readers and ports: a TQ3 / TQ4 matrix lives in the rotated basis, so rotate the input of every matrix that shares an input with a TQ matrix, whatever its storage type. Details in formats.md.
